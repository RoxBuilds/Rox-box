# Asset policy (rule #1)

**Nothing from a title is ever stored in this repository.** Everything is
built on the user's machine from files the user supplies. The same applies
to other titles used for testing, and to any other proprietary material.

[CONTRIBUTING.md](../CONTRIBUTING.md) states the clean-room rules for
contributors; this file is the reference for what the rule covers and how it
is enforced.

## Not allowed

In any form (files, string literals, fixtures, snapshots, docs, issues,
pull-request text, commit messages):

* assets: models, textures, shaders, audio, video, text, archives;
* the executable or any part of it: code, data sections, strings, tables,
  resources;
* anything derived from those: converted assets, decompiled or
  disassembled code, shader dumps, extracted tables, memory or crash dumps,
  logs of a run, screenshots;
* anything that identifies or describes one title's contents: its name or
  its publisher's, hashes of its executable or of its shaders, offsets of its
  functions or data, byte patterns that locate them, patch bytes, shader
  names;
* keys, and proprietary or leaked SDK headers, libraries or documentation.

## Allowed

* our own code that understands platform formats and APIs;
* small interoperability constants (magic numbers, enum values, interface
  ids) that we write;
* synthetic test data generated by our own code.

## Where title-specific knowledge goes

Into files the user writes and the layer reads at run time, configured in
`victory.toml` (`[paths]`) or by environment variable, never committed:

| Entry | Holds |
|---|---|
| `patches_file` (`VICTORY_PATCHES_FILE`) | byte-checked patches for the user's executable: offsets, expected bytes, replacement bytes |
| `shader_profile` (`VICTORY_SHADER_PROFILE`) | names, bindings and hashes of shaders that need special handling |
| `bcpack_tables` (`VICTORY_BCPACK_TABLES`) | the BCPack entropy models, rank tables and dictionaries (a file of 77,982 bytes) |

Their schemas are in [victory.example.toml](../victory.example.toml). With
none of them configured, the layer runs on generic, structural detection
only. The git-ignored `local/` folder at the repository root is a convenient
place for them and for `local\play.toml` (the launcher's per-title
settings).

## Exceptions

None. Even format lookup tables are not committed and must be provided by the
user at run time.

## Where data lives

Outside the repository, configured in `victory.toml`: `game_dir` (the
user's title directory), `test_titles`, `cache_dir` for derived data
(default `%LOCALAPPDATA%\victory\cache`) and `data_dir` for what titles save
(default `%LOCALAPPDATA%\victory\data`). The cache and data folders are
refused inside any copy of the source tree; `game_dir` and `test_titles`
inside one are warned about by `victory check` and `victory config`.

## Enforcement

1. `.gitignore` keeps common data types, logs and `local/` out of
   `git status`.
2. `cargo xtask policy` (run by the pre-commit hook; install with
   `cargo xtask install-hooks`) is an allowlist: files must have an allowed
   type, be under 640 KiB (Rust source: 768 KiB), contain no binary data or
   known binary signatures, and hold no long hex/base64 runs. No file may
   name a user-profile directory (`C:\Users\<name>`, `/home/<name>`), and
   when a git-ignored `local/policy-denylist.txt` exists (one literal per
   line: words match whole-word and case-insensitively, hex ids anywhere),
   no file may hold any of its literals. Exceptions need an entry with a
   reason in `xtask/src/policy.rs`; there are none.
3. At runtime, everything that writes derived data calls
   `victory_core::ensure_outside_repo`, which refuses any folder below a
   `.victory-root` marker file.
4. Tests that need real files take their paths from environment variables
   and skip when unset. They assert on properties, never on snapshots.

The local deny-list is how a contributor keeps the names and identifiers of
the titles they work with out of their own commits. It is private: never
commit it, paste it, or quote what it matched.

## If something slips through

A follow-up commit is not enough. Rewrite history
(`git filter-repo --path <file> --invert-paths`), force-push, and have
everyone re-clone.
